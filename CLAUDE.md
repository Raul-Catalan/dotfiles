# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

This is a personal NixOS system configuration using flakes + Home Manager, driving three hosts:

- **zeus** — desktop PC, AMD CPU + NVIDIA GPU, Hyprland desktop
- **hermes** — laptop, ThinkPad Carbon X1 11th gen, Hyprland desktop
- **wsl** — NixOS running as a WSL2 distro (via the `nixos-wsl` flake input), CLI-only, no desktop/bootloader/hardware modules

## Commands

Rebuilds are managed with `nh` (configured in `modules/home/cli/nh.nix`, pinned to this flake at `/home/raul/dotfiles`):

```fish
nh os switch          # rebuild and activate the current host's NixOS config
nh os switch --update # update flake inputs, then rebuild
nh os boot             # build and set as boot default without activating
nh clean all           # garbage-collect old generations
```

Equivalent raw commands (host name comes from `networking.hostName`, e.g. `zeus`, `hermes`, or `wsl`):

```fish
sudo nixos-rebuild switch --flake .#zeus
sudo nixos-rebuild switch --flake .#hermes
sudo nixos-rebuild switch --flake .#wsl
```

Inside the WSL distro, `nixos-rebuild switch` (or `nh os switch`) still works as normal — WSL2 runs a real Linux kernel and systemd under the hood. New files must be `git add`ed (even unstaged) before Nix flakes will see them, since flakes only read git-tracked paths.

Formatting/linting: `nixfmt` and `nixd` (Nix LSP) are installed as CLI tools via `modules/home/cli/default.nix`, but there is no repo-wide formatter check wired into CI — run `nixfmt <file>` manually on changed files.

There is no test suite; validate changes by building (`nixos-rebuild build --flake .#<host>` or `nh os switch`) before switching.

## Architecture

The flake (`flake.nix`) defines three `nixosConfigurations` (`zeus`, `hermes`, `wsl`), each combining:

1. A per-host system config under `hosts/<host>/configuration.nix`. `zeus`/`hermes` each also have a `hardware-configuration.nix`, not hand-edited — generated by the installer. `wsl` has no `hardware-configuration.nix`; NixOS-WSL manages its own virtual root filesystem, and it imports `inputs.nixos-wsl.nixosModules.default` for the `wsl.*` options (`wsl.enable`, `wsl.defaultUser`).
2. The `home-manager` NixOS module, with `users.raul` pointed at `home/<host>.nix`.

Configuration is split into two independent trees that mirror the NixOS vs. Home Manager boundary:

- `modules/nixos/**` — system-level modules (hardware, bootloader, audio, fonts, virtualisation, desktop). Imported from `hosts/<host>/configuration.nix`.
- `modules/home/**` — user-level Home Manager modules (Hyprland/hypr, CLI tools, apps like ghostty/vscode/nvf/anki/noctalia). Imported from `home/<host>.nix`.

`home/<host>.nix` is the per-host Home Manager entry point: it imports the shared `modules/home/**` pieces it wants, then sets host-specific `home.packages`, cursor theme, and session variables directly inline. All three hosts import `modules/home/cli/default.nix` (which fans out to individual CLI tool modules: bash, fish, git, github, helix, taskwarrior, tmux, starship, yazi, nh). `zeus` and `hermes` additionally pull in Hyprland/GUI modules (ghostty, vscode, nvf, noctalia) and differ in which Hyprland environment module they use (`hermes` sets Hyprland options inline for a non-NVIDIA setup; `zeus` imports `modules/home/hypr/environments_nvidia.nix`). `wsl` only imports the CLI module — no display server, so no Hyprland/desktop packages.

`modules/nixos/system/default.nix` holds baseline system settings shared by every host (flakes enabled, nix store optimization/GC, unfree packages allowed, timezone, minimal system packages). Host-specific system concerns (bootloader, GPU driver, CPU microcode, docker) are separate modules composed in each host's `configuration.nix`.

`modules/templates/` holds standalone `nix develop` shell templates (npm, python, rust) unrelated to the two hosts — these are dev-shell flake templates, not part of the host configs.

External flake inputs of note (see `flake.nix`): `noctalia`/`noctalia-greeter` (Hyprland shell/greeter), `nvf` (Neovim config framework, wired via `modules/home/nvf.nix`), `nixos-hardware` (ThinkPad X1 quirks, hermes only), `ucodenix` (AMD microcode).

When adding a new package or tool, prefer adding it to the relevant existing module under `modules/home/cli/` or `modules/nixos/` rather than inlining it in a host file, unless it's genuinely host-specific (screen/GPU/cursor theme differences currently live directly in `home/<host>.nix`).
